# 变更日志

本项目按“一个完整且验证过的能力，一条 `main` 分支提交”维护。每条记录说明影响、验证方式和后续配置要求。

## [Unreleased]

### Added

- 后端核心订单流自动化测试和 GitHub Actions 持续集成。
- 支付交易标识、支付状态和持久化订单事件（transactional outbox）基础。
- Alembic 数据库版本迁移与首份不可变初始 schema。
- FastAPI lifespan 生命周期管理，移除弃用的启动事件注册方式。
- 请求关联 ID 与不记录请求体/查询参数的结构化运行日志。
- 生产环境启动保护：禁止携带模拟支付、地图与打印实现上线。
- 订单操作审计记录及商家查询接口。
- 顾客“我的订单”页面和可访问的商家入口。
- 下单载荷完整性校验（坐标边界、购物车上限和去重）。
- 商家订单页可见期间的 10 秒轻量轮询与下拉刷新。
- GitHub Actions 基础 Action 升级至当前主版本。
- CI 固定 Ubuntu 24.04，避免 `ubuntu-latest` 自动迁移改变构建环境。
- 非 root Docker 运行镜像、PostgreSQL 健康检查与迁移后启动部署流程。
- 商家商品新增、编辑和上下架 API。
- 腾讯地图骑行道路距离适配器与可切换配送距离提供方。
- 微信支付 API v3 回调验签、解密、金额核对与幂等支付确认服务。
- 受专用令牌保护的打印 outbox 调度接口。

### Verified

- 顾客创建订单、服务端支付回调幂等、商家可见、订单进入制作中。
- 未绑定商家身份不能读取商家订单。
- 同一个模拟支付回调重复到达时，只创建一次打印事件。
- CI 在干净工作目录中自行创建 SQLite 测试目录。
- 每个 API 响应均包含可用于排障的 `X-Request-ID`。
- `APP_ENV=production` 会明确拒绝启动，直到真实外部服务已接入。
- 订单状态变更和补打动作可保留操作者、前后状态与时间记录。
- 订单 API 拒绝重复商品和非法经纬度。
- 不完整的微信支付生产配置会被拒绝。
